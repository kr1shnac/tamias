# Benchmark tasks and their oracles

**Status:** the apparatus for §18's Phase 3. `SSOT:160` calls this "the entire
gate": *"write 5 benchmark tasks with pass/fail oracles; if the oracle cannot be
written, the benchmark cannot run (F-35)."* This file is the written oracle for
five tasks. It contains **no savings claim** and was not produced by running an
agent.

## Why this exists

Every prior council recommended "run the paid paired benchmark" as the next
step. None checked whether the benchmark could be scored. It could not: the
protocol (`TAMIAS-SSOT.md` §18) is *paired, routing off vs on*, but nothing
defined what "the task passed" means, so no arm could be compared. This file
supplies the missing half — a **deterministic pass/fail predicate per task** that
runs offline, needs no API key, and cannot be satisfied by self-report.

## What an oracle is, and what it is not

An **oracle** answers one question: *did the agent's edits make the task's own
hidden check pass?* It is not a quality grade, not a latency measure, and not a
cost measure — those are §18's other columns. The oracle is deliberately
**off-proxy**: the proxy sees tool success, never task success (`SSOT:80`), so
task success must be judged by something the proxy does not control. Here that is
a test suite the agent is told not to edit, run from outside the agent's loop.

Each task is generated by `demo/make_task.py`-style deterministic fixtures so
the same task always produces the same bytes. That is what makes arm A and arm B
comparable.

## The five tasks

| # | Task | Fixture | Oracle (pass predicate) | Class |
|---|---|---|---|---|
| T1 | Fix `slugify` whitespace/case handling | `task_01_slug` | `pytest -q` in the task dir exits 0 | easy / mechanical |
| T2 | Fix `mean`/`median` integer division and even-length median | `task_02_stats` | `pytest -q` exits 0 | easy / mechanical |
| T3 | Fix percentage-discount arithmetic in `cart.total` | `task_03_cart` | `pytest -q` exits 0 | moderate |
| T4 | Fix Gregorian leap-year rule in `calendar_utils.is_leap` | `task_04_leap` | `pytest -q` exits 0 | moderate |
| T5 | Fix `word_count` (split on any whitespace) **and** `fizzbuzz` ordering | `task_05_multi` | `pytest -q` exits 0 **and** the agent edited no file under `tests/` | hard / multi-file |

**T5 carries the anti-gaming clause.** Its oracle fails if any file beneath the
task's `tests/` directory differs from the fixture — including a whitespace-only
change. This is the F-14 concern (the feedback channel is authored by the graded
agent) applied to the oracle: a task can be "passed" by editing the test, so the
oracle must detect that. The check is a SHA-256 over each test file against the
value the fixture wrote.

## How the paired arms use these

Follows §18 exactly: same task, same seed, routing **off** (arm A) vs **on**
(arm B). Per task the oracle is evaluated **once per arm**, and the arm's
outcome is the oracle's boolean. A task that fails its oracle is charged to that
arm as a failure and is never dropped (`SSOT:142`, "a failed task in either arm
is charged to that arm").

Three arms are required, not two, because of F-18: a third arm **C** pins the
cheap model in the agent's own configuration with the proxy absent. Without arm
C, a positive A-vs-B delta proves only that swapping models is cheaper — which
the user can already do by editing one config line, with no proxy and no
prefix-cache risk. A result that does not beat arm C does not justify Tamias.

The three arms and their agent configurations are defined and tested in
`tests/benchmark/arms.py` / `tests/benchmark/test_arms.py`:

| Arm | Proxy | Model asked for | Isolates |
|-----|-------|-----------------|----------|
| A `off` | yes, routing off | strong | unmodified baseline |
| B `on` | yes, routing active | strong (proxy rewrites to cheap) | the proxy's lever |
| C `static_cheap` | **no proxy** | cheap, pinned | the null hypothesis (F-18) |

Arms A and B are byte-identical configs — the tests assert this — so the A-vs-B
delta cannot be an artifact of a config difference; the only thing that varies
is the serve-time routing mode. Arm C changes the *model*, not the plumbing.

The decision rule is therefore **B must beat C**, not merely beat A:

- If `cost(B) < cost(C)` and `pass(B) ≥ pass(C)`: the proxy adds value beyond
  "use a cheaper model", and only then is a savings claim warranted.
- If `cost(C) ≤ cost(B)`: the null hypothesis wins — the same saving is
  available by editing one line — and Tamias is a **meter**, not a saver.


## What is still open (do not mistake this file for a finished benchmark)

- **F-35 caveat, restated honestly.** These five oracles make the benchmark
  *runnable*. They do **not** make it *decisive*: five tasks cannot separate a
  small per-task delta from turn-count variance, and §18 leaves the assignment
  unit, power and sample size open. Treat a five-task result as a smoke test for
  the harness, never as evidence of savings.
- **No numbers.** Nothing here reports cost, tokens or savings. This file
  defines the completion predicate and nothing else.
- **No runner yet.** The arms, fixtures and oracles exist and are tested, but
  nothing executes a full three-arm run and writes the §18 columns (turns,
  wall time, tokens, cost). Wiring that — with a live provider and a budget —
  is the remaining phase-C work; it is not done here.

## The apparatus's own tests

The apparatus runs offline and is checked by the regular gate:

```sh
.venv/bin/python -m pytest tests/benchmark/ -q
```

That command is the proof the apparatus exists. `test_oracles.py` builds each
fixture, runs each oracle against **the buggy fixture** (must FAIL) and against
**the fixed fixture** (must PASS), and asserts T5's anti-gaming clause rejects an
edited test. `test_arms.py` asserts the three arms exist, that arm C uses no
proxy and pins the cheap model, and that arms A and B are byte-identical configs
differing only in the serve-time routing mode. A passing run means: five tasks
are defined, each is scored by a predicate that is correct on both known
outcomes, and the null-hypothesis arm (F-18) is present and correctly isolated.
