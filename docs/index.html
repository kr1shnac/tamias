One row for every request your agent makes.

Tamias is a local proxy that sits between your coding agent and the model API. It records which model ran, how many tokens it cost, and what that cost was (exact or UNKNOWN, never guessed) — and it can send a request to a cheaper model when a configured rule says that is safe.

Alpha · metering proven; savings estimated, not yet measured.

What it is

A transparent, OpenAI-compatible request-rewriting proxy. No service or database to install — the log is a local SQLite file.

Point your agent at Tamias instead of at the provider. Requests pass through unchanged by default; the router records a STAY or SWITCH decision, the reply comes back to the agent untouched, and one row lands in the local log. Requires Python 3.11 or newer.

Install

Not yet published on PyPI — install the reviewed source. The one-liner above and the steps below are equivalent.

git clone https://github.com/kr1shnac/tamias
cd tamias
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install .
tamias --version            # tamias 0.1.0a8

Quickstart

Fetch a price sheet, check the local setup, then start the proxy.

tamias prices fetch --out prices.toml
tamias doctor --prices prices.toml
tamias serve --upstream https://openrouter.ai/api --prices prices.toml --db requests.db

Point your agent's base URL at http://127.0.0.1:8000 instead of the provider, and its traffic flows through the proxy. When you are done: 

tamias dashboard --db requests.db --prices prices.toml

How it works

One request, end to end.

Your coding agentOpenCode · Codex · Claude Code
→
Tamias proxyparse → router → forward · 127.0.0.1:8000
→
Provider APIOpenRouter · OpenAI · Ollama
↩ the provider's reply returns to the agent unchanged
one row per request — model · tokens · cost → SQLite log requests.db → tamias report / tamias dashboard

Routing is rule-based, not model-scored. The default mode is shadow: Tamias records the decision it would make and forwards the request unchanged, so the default install cannot alter your traffic. Active mode (--router-mode active) rewrites the model only when a configured rule fires, and refuses to start unless the target is named in --registry, tool-capable, and priced.

Status

What is proven, and what is not. The full ledger lives in TAMIAS-SSOT.md and docs/audit/claims.md.

Proven

Metering. Tokens and cost are recorded per request; cost is exact or UNKNOWN, never guessed. Prompt and response text are never stored.

Proven

Rule-based routing. Shadow mode records decisions without rewriting; active rewriting is opt-in and fail-closed behind startup gates.

Unverified

Live behaviour. Tested on fixtures only: live provider behaviour and real Codex and Claude Code traffic are unverified.

Not measured

Savings. Estimated, not yet measured — no measured savings exist, and every figure in this project is hypothetical. Treat any percentage as an illustration, not a measurement.

Local by default

  • Binds loopback only (127.0.0.1). Exposing it off your machine is a two-key act: --auth-token (or $TAMIAS_AUTH_TOKEN) and --allow-non-loopback must both agree, or serve refuses to start.
  • Nothing sensitive is stored: no prompt or response text, no credentials. The credentials your client already sends are forwarded to the provider, not kept.
  • Company keys (opt-in, --keys-db) give per-caller identity and a model allowlist: only the key's SHA-256 hash is stored, and the secret is shown exactly once. Keys are identity, not spend caps — see docs/KEYS.md.

What Tamias does not do

  • It does not proxy arbitrary web traffic — only the three routes above are metered; everything else is passed through counted-only, never priced.
  • It does not store prompt or response text, and it does not log credentials.
  • It does not authenticate with the upstream provider; it forwards the credentials the client already sends.
  • It does not rewrite requests unless active mode is on and every startup gate passes — by default it cannot change which model a provider actually runs.
  • It does not prove that a provider honoured a requested reasoning effort; the log records the request only.
  • It does not measure savings. Metering is proven; savings remain estimated.
